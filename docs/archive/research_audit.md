# Research Audit and Proposed Final Pipeline

*Audit of `research-next` @ `34cfafe`, performed by inspecting code, commit history, training configs, and result metadata only. No experiments were executed to produce this document — every claim below is either a direct file/config read or a `git log`/`git show` provenance trace.*

---

## 0. Executive summary — read this first

Three things surfaced that change how the rest of this document should be read:

1. **I made a checkpoint-provenance error in the last several turns of this conversation.** The project has an official, authoritative 5-seed PPO checkpoint batch (`e5_ppo_s{42..46}_anneal_linear`, trained 2026‑09‑05/06/23) that every aggregation script in the repo (`c2_aggregate_multiseed.py`, `c3_combined_gap_table.py`) is hard-coded to use. There is also an **older, abandoned, pre-costing-fix batch** (`gated_cost_merged_seed{42..46}`, trained 2026‑09‑01) that no aggregation script references. In this conversation, I mistakenly instructed reruns of the OOD extrapolation test, the corrected GA/DE-vs-PPO comparison, and the hand-calculation comparison using the **wrong (old) batch**. Section 3 traces exactly which recent deliverables this affects and what needs to be rerun.
2. **There are two unrelated, sequential "corrected ground truth" events in this project's history, and they are easy to conflate.** E1 (2026‑09‑03) fixed an exploitable rolled/welded costing defect (physics/manufacturability-level). My fix (2026‑09‑26) corrected miscalibrated S460/S690 price coefficients (economics-level). `pretrain_data_corrected/` reflects only the first; `pretrain_data_corrected_v2/` (cost only) reflects both. Nothing before 2026‑09‑03 is trustworthy for any headline claim; nothing before 2026‑09‑26 has the calibrated grade economics.
3. **No RL policy has ever been trained for the mass or CO₂ objective.** Every trained checkpoint in the repository (PPO, SAC, TD3, DDPG) used `economy_metric=cost` exclusively. Mass/CO₂ ground truth and classical-baseline (GA/DE) results exist, but any claim about RL performance on mass or CO₂ is currently unsupported — there is no checkpoint to evaluate.

This should be fixed by generating 5 separate per-seed files (matching the convention `e5_ppo_s{seed}_..._per_context.csv` already uses) rather than one merged file, whenever ExpA5 is rerun.

## 5. Proposed final authoritative pipeline (spec only — not executed)

1. **Physics (unchanged, not in question):** `HSSBeamEnv._ec3_analysis()`, EC3 Class 1-4 checks, moment/shear capacity — untouched by either fix, no changes proposed.
2. **Ground truth:** regenerate mass, cost, and co2 together into **one** new directory (e.g. `pretrain_data_v3/`) using the current `hss_env.py` (E1 fix + material-cost fix both present), for the main 142-context grid and all three OOD grids. Add a `meta.json` alongside the CSVs recording: git commit hash of `hss_env.py`/`regenerate_ground_truth.py` at generation time, script args, and generation date — closing the provenance gap in Section 2.
3. **Train/val/test split:** the existing 142-context grid (12×12 span/load, excluding box-infeasible combinations) as train-time sampling range and evaluation grid; OOD grids as held-out generalization tests. No change proposed here — this part is already sound.
4. **Objectives:** cost remains primary (the only one with a trained policy). Mass/CO₂ stay GA/DE/kNN-baseline-only unless a decision is made to actually train PPO for them (a real training run, not a rerun — flagged as optional, high-cost, in the rerun plan below, not assumed necessary).
5. **PPO configuration:** `feasibility_gated` reward, `log_std_anneal: True`, `economy_reward_mode: log_relative` — i.e. the E5-established best configuration — retrained from scratch under `pretrain_data_v3`'s cost coefficients, 5 seeds, 1M steps each. This is the one training run (not just re-evaluation) the audit shows is actually missing: no 5-seed batch currently exists that is both E1-fixed and material-cost-fixed at training time.
6. **GA/DE baselines:** rerun matched-budget sweep (`expA2_pipeline_baselines.py`) against `pretrain_data_v3`, once the new PPO batch exists, so PPO and baselines are compared on identical ground truth.
7. **kNN/amortized baseline:** rerun `expA3_amortized_baselines.py` against `pretrain_data_v3` — this is a re-evaluation of an existing, cheap method, not a new training run.
8. **Repair (`scale+thin`):** unchanged; already deterministic and metric-agnostic, just needs to be run against current ground truth each time, as it always has been.
9. **Multi-seed protocol:** 5 seeds (42-46), as already established; report mean, median, and paired bootstrap CIs against every baseline at matched budget, not just against the single strongest one.
10. **OOD protocol:** rerun span/load extrapolation against regenerated OOD ground truth, with the correct PPO checkpoint batch, and fix the seed-parsing defect (Section 4) so cross-seed variance is actually reported. Joint extrapolation remains untestable (zero feasible ground truth) and should be stated as such, not silently dropped.
11. **Statistical reporting:** paired bootstrap CIs (already the convention in ExpA2/ExpA5's `compare()`/`matched()` functions) plus explicit training-cost amortization breakeven (already computed in `expA2_*_equivalence.csv`) — keep both, they are already the right standard, just need re-running on consistent data.

## 6. What can be reused vs. what must be rerun

**Reusable as-is (no rerun needed):**
- EC3 physics/repair code — no changes proposed.
- `pretrain_data_corrected/ec3_optimal_designs_mass.csv` — mass has no cost-factor dependency, still current.
- E3, E4 docs' qualitative conclusions (algorithm ranking, retrain-recovers-~40%-of-gap finding) — diagnostic scope, already labeled as such, do not need to be re-litigated.
- The reference-design costs and environment's-own-optimum number in the hand-calc writeup (checkpoint-independent).

**Must be rerun before being called authoritative:**
- ExpA2_corrected, ExpA5 OOD (PPO leg), ExpA7 — wrong checkpoint batch (my error).
- ExpA, ExpA2 (original), ExpA3, ExpA5 (kNN + GA/DE legs) — correct checkpoint or no checkpoint, but stale (pre-material-cost-fix) ground truth.
- A genuine, new 5-seed PPO training run under fully-corrected ground truth does not exist anywhere in the repository yet — this is the one item that is a real gap, not just a stale re-evaluation.

**Optional, not required for internal consistency:**
- Retraining PPO for mass/CO₂ objectives.
- Re-running Exp1's reward-mode ablation post-E1 (interesting, but the project already committed to `feasibility_gated` and re-litigating reward-mode choice isn't necessary for the paper's current scope).

## 7. What I am NOT proposing yet

No code changes, no reruns, and no manuscript edits have been made as part of this audit. The one substantive new training run this audit identifies as necessary (item 5 above) is expensive (5× 1M-step PPO runs) and should not be started without your explicit sign-off, per your instructions. Everything else in the rerun plan is re-evaluation of existing artifacts against corrected ground truth and/or the correct checkpoint batch, at the same low computational cost as the OOD/matched-budget reruns already done earlier in this conversation.
